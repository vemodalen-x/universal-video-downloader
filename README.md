# Universal Video Downloader for Windows

一个用于学习和研究视频下载流程的 Windows 桌面工具。项目提供 HLS/m3u8、普通视频直链、百度网盘授权分享、PikPak 公开分享和 YouTube 链接的解析与下载能力，重点演示播放列表解析、分片下载、断点续传、音视频合并和桌面客户端交互。

> 本项目仅作为学术研究、技术学习和个人合法备份示例开源。请勿用于商业用途，请勿下载、传播或再分发没有授权的内容，请勿规避 DRM、访问控制、付费限制或版权保护机制。

当前稳定版本：`v1.2.0`。完整更新记录见 [CHANGELOG.md](CHANGELOG.md)。

## 功能

- 输入网页 URL、百度网盘分享、PikPak 公开分享、`.m3u8` URL、普通视频直链或 YouTube 视频 URL。
- 识别带四位提取码的百度网盘分享，通过用户已授权的本地连接器转存并下载完整分享目录；下载结果未确认完整时不会标记成功。
- 解析 PikPak 公开分享中的视频和嵌套文件夹；受保护的分享可在高级选项中输入提取码。
- 自动扫描网页源码和外链脚本中的 HLS/m3u8 地址。
- 静态扫描没有结果时，自动切换到 `yt-dlp` 通用网页解析器。
- 通用网页解析可通过 `curl_cffi` 使用浏览器 TLS 指纹兼容请求，改善部分 Cloudflare 保护页面的公开媒体发现能力。
- 自动识别普通视频直链，例如 `.mp4`、`.webm`、`.mov`、`.mkv`、`.m4v`。
- 使用 `yt-dlp` 支持 YouTube 视频解析、下载和音视频合并。
- 提供 Chrome/Edge 浏览器伴侣：用户主动点击后检测当前标签页已经加载的公开 HLS、DASH 和视频直链，并发送到桌面端解析。
- 支持 yt-dlp 播放列表展开、多选和顺序批量下载，单个失败不会中断剩余队列。
- 媒体列表支持标题/来源关键词搜索和标题自然排序（第 2 项排在第 10 项之前）；只下载当前可见的选中项，执行顺序与列表一致。
- 队列启动前原子保存全部待下载条目；停止或退出后，尚未轮到的项目也能在任务记录中找到。当前会话可一键重试未完成项，保留原路径和记录标识。
- 提供最佳质量、最高 1080p、最高 720p 和较小文件四种下载策略。
- 解析并展示可用格式的分辨率、帧率、HDR、音视频编码、码率、大小和协议。
- 可选择人工字幕或自动字幕，输出 SRT、VTT、ASS，并在 FFmpeg 可用时嵌入视频。
- 自动解析 HLS master playlist，并默认选择分辨率/码率较高的清晰度，支持 `EXT-X-BYTERANGE` 复用资源分片和初始化段。
- HLS 分片并发下载，支持暂停、继续、停止和失败后续传；临时签名变化后仍按稳定媒体标识复用原分片缓存。
- 普通 HTTP 视频使用内部恢复缓存和固定大小的显式 Range 请求实现断点续传；连接中断后会在有限次数内从最新字节位置自动重试，并兼容拒绝开放字节范围的媒体服务器。
- 续传时校验服务器 `Content-Range` 起止位置并使用未压缩字节流；响应不匹配时保留内部缓存，目标目录只生成校验完成的正式视频。
- 拒绝把空响应、错误网页或播放列表文本保存成视频；服务器提供强 ETag 时，续传会校验文件版本，并在重启后继续使用哈希校验信息。
- PikPak 临时媒体地址失效时，会按稳定文件标识在内存中刷新地址并继续已有断点，提取码不会写入磁盘或日志。
- 多文件队列严格串行；可恢复错误会在当前文件上进行最多 3 次队列级尝试，连续失败后保留内部续传缓存并继续处理下一项。
- 下载前自动识别重复选择、保存文件夹中已存在的同名文件和仍可访问的已完成记录；命中后直接跳过，不覆盖、不改名，也不重复下载。
- 支持常见 HLS AES-128 加密分片。
- 自动重试临时网络错误，并尊重服务器的 `Retry-After` 限流指示。
- 按访问拒绝、链接失效、限流、服务器异常、磁盘权限等类别提供恢复建议。
- 本地任务记录支持完成、失败、停止和异常退出后的状态恢复；选择失败、停止或中断记录后可直接点击“继续下载”。
- 下载进度采用限频刷新、平滑速度和 ETA，长播放列表使用聚合状态块避免界面卡顿。
- 准备、未知大小和封装阶段使用忙碌进度；已知进度平滑过渡，不超过实际报告值。暂停、停止和完成会停止动效，高级选项提供本次会话的“减少动效”开关。
- 任务历史按行增量刷新，保留选中项和滚动位置；任务完成后记录实际输出格式、文件路径和大小，历史文件更新使用跨进程互斥锁。
- 日志和历史记录会移除 URL 用户信息、查询参数、临时签名及常见 Token 字段。
- 使用适配 Windows 16/32/64/256px 的专业品牌图标，窗口、EXE 与桌面快捷方式保持一致。
- 可保留本地缓存，便于下载中断后继续。

## 支持的视频类型

| 类型 | 支持情况 | 说明 |
| --- | --- | --- |
| HLS / m3u8 | 支持 | 支持 master playlist、多清晰度、普通/字节范围分片、初始化段、续传和 AES-128 |
| 普通视频直链 | 支持 | 支持 mp4、webm、mov、mkv、m4v 等常见扩展 |
| 百度网盘分享 | 支持 | 通过随 Windows 便携包提供的 BaiduPCS-Go 连接器处理；需要用户自己的百度账号授权、可用网盘空间和正确提取码 |
| PikPak 公开分享 | 支持 | 支持可匿名访问的分享、提取码、完整嵌套文件夹遍历和不限数量的视频候选；直链支持断点续传和过期地址刷新 |
| YouTube | 支持 | 通过 yt-dlp 解析，通常需要 ffmpeg 合并音视频 |
| 通用网页媒体 | 支持 | 静态扫描失败后通过 yt-dlp 的站点提取器尝试解析 |
| 浏览器当前页检测 | 实验性支持 | Chrome/Edge 主动检测，不读取 Cookie，不常驻监听浏览历史 |
| DASH / MPD | 部分支持 | yt-dlp 能识别的公开资源可下载，尚无原生 MPD 解析器 |
| DRM 内容 | 不支持 | 不绕过 Widevine、FairPlay、PlayReady 等 DRM |

## 安装运行

建议使用 Python 3.11 或更高版本。当前代码也可在 Python 3.10 下运行，但 `yt-dlp` 已提示未来会逐步弃用 Python 3.10。

```powershell
python -m pip install -r requirements.txt
python m3u8_desktop_app.py
```

默认保存目录：

```text
%USERPROFILE%\Downloads\Video Downloader
```

## 使用流程

1. 在“添加媒体链接”中粘贴视频页面 URL、百度网盘分享、PikPak 分享、`.m3u8`、普通视频直链或 YouTube 链接。
2. 点击“解析媒体”，客户端会按专用 yt-dlp 提取器、静态扫描、HLS 解析和通用提取器查找媒体。
3. 播放列表默认选择第一项，可按住 `Ctrl` 或 `Shift` 多选，也可点击“全选”或“取消选择”；媒体列表内支持 `Ctrl+A` 全选和 `Esc` 取消选择。普通链接会选择推荐项。
4. 在右侧确认保存位置、质量策略和字幕选项；单项可编辑文件名，多项按各自标题命名。不适用于当前媒体的质量和字幕设置会禁用。“格式详情”可查看当前条目的技术参数。
5. 点击“开始下载”或“下载选中项”；保存文件夹中已有同名文件或存在可用的已完成记录时，客户端会自动跳过并显示数量，只下载缺少的项目。
6. 百度网盘首次使用时，打开“高级选项”设置窗口并点击“连接百度网盘”，在独立连接器终端完成自己的账号登录；客户端不会读取终端输入。
7. 分享要求提取码或提取码错误时，会自动打开高级设置并聚焦提取码输入框；输入后按回车重新解析。百度网盘为四位，PikPak 按分享者提供的完整内容输入；也支持链接中的 `pwd` 或 `s_code` 查询参数。
8. 需要手动设置 `Referer`、并发数或缓存策略时，也可使用“高级选项”。并发数必须是 1 到 32 的整数，输入错误会保留当前媒体并提示修正。
9. 下载失败、停止或异常中断后，在“任务记录”选择对应项目并点击“继续下载”；客户端会重新确认媒体、恢复原文件名，并复用内部恢复缓存、HLS 分片、连接器断点或 yt-dlp 临时文件。

更换链接后旧媒体、旧进度及该来源的提取码和 Referer 会清空，需要重新解析。解析或下载期间，来源与保存设置暂时锁定，避免重复启动或中途改动不生效；下载结束后恢复编辑。取消全部选择会同步禁用下载按钮。

搜索支持多个关键词，不区分大小写；筛选隐藏的项目会取消选中，清空搜索不会偷偷恢复它们。“全选”只选择筛选结果。选择“标题升序/降序”后，批量下载按屏幕上的顺序执行。

停止或部分失败后，可在底部点击“重试未完成”，继续本次队列中失败或尚未开始的文件，仍逐项重试后再推进下一项，保存到原位置，不使用后来修改的目录或文件名。已完成或目标文件已存在的项目不会重复下载。受提取码保护的分享需要重新输入提取码；更换来源后该快捷恢复队列会清空。重启后的未完成项保留在“任务记录”的“未完成”筛选中，可逐项“继续下载”并重新确认来源。

HLS 下载期间可用“合并部分”导出已完整下载的分片，生成带 `.partial` 标记的预览文件；它不代表整个视频已下载完成。没有可用分片时不会生成空文件，重复点击不会并发导出，导出失败不影响原下载队列。完整合并和缓存清理会等待当前导出结束。

任务记录底部显示所选任务的状态或失败原因。“打开文件夹”按媒体类型定位保存目录；原目录已移除时打开最近仍存在的上级目录，不会创建空目录，磁盘未连接时在当前页提示。

活动日志只读，最多保留最近 2000 行，单条内容经脱敏后限制为 1000 字符；Authorization、Cookie、查询签名及提取码不会原样显示。查看较早日志时，新日志不会强制跳到底部，滚回底部后恢复跟随。

## 浏览器伴侣

浏览器伴侣用于补充动态页面发现能力。扩展只有 `activeTab`、`scripting` 和 `nativeMessaging` 权限；只有用户点击“检测当前页面”时，才会读取当前标签页 DOM 与 Resource Timing 中已经加载的公开媒体地址。

正式便携包中的安装步骤：

1. 在桌面端点击“连接浏览器”并确认；也可手动运行 `install_browser_companion.ps1`。
2. 打开 `chrome://extensions` 或 `edge://extensions`，开启“开发者模式”。
3. 点击“加载已解压的扩展程序”，选择安装脚本输出的扩展目录。
4. 在视频页面先播放几秒，点击扩展图标和“检测当前页面”，再把候选发送到桌面端。

浏览器发送的媒体地址会进入最多 20 条、15 分钟过期的本地收件箱。收件箱使用 AES-GCM 加密；Windows 上密钥由当前用户 DPAPI 保护。扩展不会接收或发送 Cookie、Authorization、账号密码和浏览器历史。

## 本地数据与隐私

任务记录默认保存在：

```text
%LOCALAPPDATA%\UniversalVideoDownloader\history.json
```

历史文件只用于本机任务管理，默认保留最近 2000 条已完成任务；未完成任务不受此保留数量限制，并在原子更新前保留一份可恢复备份。来源地址写入前会移除用户名、密码、查询参数和片段；YouTube 使用不含查询参数的规范视频 ID 路径。重复检测只保存由脱敏来源或稳定媒体标识生成的 SHA-256 指纹，不保存原始签名链接。错误日志会隐藏常见 Cookie、Authorization、Token 与签名字段。网盘提取码仅保留在本次解析和下载进程的内存中，队列结束或解析失败后清空，不写入候选、历史或日志。输出文件路径会保留，以便从客户端打开保存目录。应用不会把任务历史上传到服务器。

媒体去重会保留 `id` 等资源选择参数参与哈希计算，并排除常见临时签名参数，避免不同视频被错误合并；参与计算的参数不会原样写入历史。直链续传目录中的 `metadata.json` 仅保存声明大小和强 ETag 的 SHA-256，不保存网址或提取码。

百度账号登录由独立的 BaiduPCS-Go 连接器处理，桌面客户端不接收账号、密码或 Cookie。连接器会按其自身规则把授权状态保存在 `%APPDATA%\BaiduPCS-Go`；退出账号或删除该目录可清除连接器授权。请勿把该配置目录加入发布包、截图或问题附件。

## 当前限制

- 工具不会导入浏览器 Cookie、登录会话或受保护的用户数据。必须登录后播放的页面可能无法解析。
- 百度网盘分享必须使用用户有权访问的账号完成转存，并占用该账号的网盘空间。连接器不提供超出官方客户端权益的提速，不绕过登录、验证码、限流或会员限制。
- 百度分享链接中的 `#list/path=...` 是网页端路由。本版本把整个分享根目录作为一个批量任务处理，不承诺只下载浏览器当前显示的嵌套子目录。
- BaiduPCS-Go 使用独立的上游实现，可能随百度接口变化而失效；登录或转存被拒绝时，应先在浏览器和官方客户端确认账号及分享状态。
- PikPak 仅支持用户有权访问的公开分享。工具不登录账号、不读取私人网盘、不获取缺失的提取码；出现人机验证时会停止并提示使用浏览器伴侣，不自动绕过验证。
- PikPak 返回的媒体地址通常带有有效期。下载期间失效时客户端会自动刷新并续传；若分享本身失效、人机验证出现或服务器拒绝 Range，请确认分享仍可访问后重新解析同一文件。
- 若服务器声明文件版本或大小发生变化，客户端保留缓存并停止追加；请重新解析并选择新的文件名完整下载。未提供强 ETag 的服务器只能进行范围和大小校验，不能保证识别所有同大小内容替换。旧直链缓存因媒体识别规则修正可能需要重新下载。
- 桌面端自身不执行第三方页面脚本或常驻监听；浏览器伴侣只在用户点击“检测当前页面”时注入隔离扫描，高度动态的网站仍可能需要站点支持或用户提供公开媒体地址。
- 浏览器伴侣只查看页面已经暴露给 DOM/Resource Timing 的资源；跨域受限 iframe、`blob:` MediaSource、隐藏接口和 DRM 播放器可能无法发现。
- 浏览器伴侣当前通过开发者模式安装，尚未提交 Chrome Web Store 或 Edge Add-ons，也暂未支持 Firefox。
- `yt-dlp` 的站点支持会随上游网站变化。遇到解析回归时，先升级 `yt-dlp` 并查看活动日志。
- TLS 指纹兼容只改善普通网页请求，不会自动完成 CAPTCHA 或登录验证；仍显示验证页时，请在浏览器完成验证并通过浏览器伴侣发送已加载媒体。
- YouTube、DASH 以及分离音视频流通常需要系统 PATH 中可访问 `ffmpeg`。
- 未安装 FFmpeg 时会选择无需音视频合并的单文件格式；字幕仍可单独保存，但不能转换或嵌入视频。
- 播放列表和 PikPak 分享不设置媒体数量硬上限；超大列表会完整解析，因此候选加载时间和内存占用会随条目数量增加。
- 重复检测依据稳定媒体标识、脱敏后的媒体地址、已完成记录和目标文件名；同一内容若来自完全不同的镜像地址且文件名也不同，除非执行耗时的整文件内容哈希，否则无法自动判定为同一视频。
- 旧版本已经写入历史且必须依赖查询参数的页面可能无法直接继续；客户端会要求重新粘贴原链接。受提取码保护的分享也需要用户重新输入提取码，客户端不会从历史恢复凭据。
- 历史任务有媒体指纹时必须精确匹配；只有一个解析结果也不会自动替代原视频。无法匹配时需手动选择，避免下载到原任务的错误文件名下。

## 打包为 exe

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\build.ps1
```

发行构建使用 `requirements-release.txt` 中固定版本及 SHA-256 wheel 哈希的 Windows 依赖，并在隔离虚拟环境中执行。构建脚本还会下载固定的 BaiduPCS-Go v4.0.2 Windows x64 包，同时校验上游 ZIP 与 EXE 的 SHA-256 后才放入便携目录。GitHub Release 工作流固定官方 Action 的提交 SHA 和 Windows Runner 版本。构建完成后会自动执行源码与 ZIP 脱敏扫描，并生成：

```text
dist\UniversalVideoDownloader\UniversalVideoDownloader.exe
dist\UniversalVideoDownloader-v1.2.0-windows-x64.zip
dist\SHA256SUMS-v1.2.0.txt
```

当前版本会把图标和 `yt-dlp` 一起打入 exe。若需要更稳定的 YouTube 音视频合并，请确保系统 PATH 中可访问 `ffmpeg`。

构建还会生成 `UniversalVideoDownloaderBridge.exe`，并把 `browser-extension`、`install_browser_companion.ps1`、`BaiduPCS-Go.exe` 及其 Apache-2.0 许可证放入同一便携目录。

品牌主图位于 `assets/app_brand_v2.png`，Windows 多尺寸图标位于 `assets/app_icon_v2.ico`。旧版图标仍保留在仓库中用于版本追溯。
